# Framebuffer text console

Status as of 2026-10-31, payload build `20261031-173828` (`firmware`: `console.c`, `console.h`, `font8x16.h`, `gen_font.py`, the "framebuffer console" section of `net.c`). Display facts come from [display_touch.md](display_touch.md); the owner confirmed earlier that OSD0 reads ARGB8888 from little-endian words.

## What it shows

The panel is 1024x600. The top 192 pixels hold a six-row status panel at scale 2 (16x32-pixel cells, 64 columns): build id and uptime; IP, SSID, channel, RSSI and join state (green when up with an address); interrupt state, tick count, heartbeats, USB errors and TX count; MCU ACC bytes, version string, MCU time and date; the last crash (red) or "crash: none"; the last `say` line (cyan). Below a blue rule is the tail of the payload's log: at scale 2 that is 12 rows of 64 columns, at scale 1 25 rows of 128 columns (`hu.py fb scale 1|2`). Long log lines wrap. Lines starting with `!` or `join` are drawn in yellow.

## How it works

- Frame: 1024x600x4 = 0x258000 bytes at **0x03400000**, region header (128 bytes) at **0x03660000**. These avoid U-Boot (heap 0x077B3000–0x07CC3000, relocated code above), the payload (0x01800000–0x01900000), its log (0x01A00000–0x01AF0000), the HU1 reply buffer (0x02000000), WIFI.TXT (0x02100000), the crash record and vectors (0x01F00000–0x01F1FFFF), the EXEC trampoline (0x02F00000) and `hu.py`'s upload area (0x03000000–0x030FFFFF; `tools/fb.py` uses 0x03000000–0x032F007F).
- Enable (`fb_enable`, at the start of `main`): clear the frame, build the header exactly as U-Boot `sub_f1fe84` / `tools/fb.py` do (format 0x0E ARGB8888, 600x1024, stride 1024, end-of-list link, data address), write the D-cache back over frame and header, then U-Boot's own two writes: `0x9C006208 = header`, `0x9C006204 = 1`.
- Redraw (`console_poll`): at most every 500 ms, from the main loop and from `hb_tick` (so it keeps updating during the Wi-Fi bring-up), never from the ISR. `console.c` keeps the wanted and the shown text of every row and redraws only rows whose text or colors changed. After each redrawn row it writes the D-cache back over that row's pixels (128 KB for a scale-2 row). An unchanged screen costs nothing; the uptime makes the first panel row change every second; a new log line redraws the log rows.
- Font: 8x16, printable ASCII plus a box for anything else, generated by `gen_font.py` from `LatGrkCyr-8x16.psfu.gz` (kbd package; Ken Moffat's sigma font; its README says "The font is public domain"). Glyphs are scaled by pixel replication.
- Host test: `test/test_console.py` drives `console.c` through `test/con_host.c`, checks the dirty-row accounting (first render 18 rows, then 0, one changed row = 1 row and 128 KB written back, scale 1 = 25 rows), checks that every pixel is opaque, and can write a PNG of the screen.

## Remote control

HU1 op 0x0C FB (payload `u8`: 0 off, 1 on, 2 status, 3 log scale + `u8` 1/2) and op 0x0D SAY (text shown in panel row 6 and logged as `say: ...`). `hu.py fb status|on|off|scale N` and `hu.py say TEXT...`. The status reply includes OSD0 ctrl/en/link and the hardware checksum.

## Live evidence (2026-10-31)

`hu.py fb status` on build `173318` returned `osd0 ctrl=437 en=1 link=3660000` with the checksum changing on every read while the console redrew: 0x6F66, 0xE0A4, 0x6C2B, then 0x99E4 after a `say`. On build `173828`: 0x5314, then 0x6EDA three seconds later. The checksum alone doesn't prove the text looks right; the owner needs to confirm what the panel shows.

## Card logging

Since build `20261031-175013` the log lives in RAM, on the screen and behind `hu.py log`. It goes to the card only for a crash report (once, `C<crc>.TXT`) and on the MCU's shutdown request (`S<hex>.TXT`), through a 64-byte-aligned bounce buffer.

## Not done

- No double buffering: a row can tear for one frame while it is being redrawn. Two frames with a `link_addr` flip would fix it if it is visible.
- The backlight is whatever U-Boot left on; nothing here touches PWM or the MCU's `EE` command.
- No touch input yet (see display_touch.md for the open GT9xx questions).
